# แดชบอร์ดรายงาน

ทางเข้าทั้ง 4 แบบอยู่ส่วนบนของ `/reports` คลังรายงานมาตรฐาน การส่งออก PDF/XLSX และการตั้งเวลารายงานเดิมยังใช้ `ReportsHub` และเส้นทางเดิมโดยไม่เปลี่ยนการทำงาน

| เส้นทางใหม่ | ข้อมูลที่สรุป |
| --- | --- |
| `/reports/dashboard/budget` | คำของบประมาณในปีที่เลือก แยกวงเงินตามหน่วยงานและจำนวนตามสถานะ |
| `/reports/dashboard/projects` | โครงการในปีที่เลือก งบอนุมัติ สถานะ และความก้าวหน้า |
| `/reports/dashboard/disbursements` | รายการเบิกจ่ายทั้ง 4 ไตรมาสในปีที่เลือก แยกยอดกระทบยอดแล้ว |
| `/reports/dashboard/kpi` | ผล EdPEx และ AUN-QA ของไตรมาสที่เลือก พร้อมผลรายปี |

ปีและไตรมาสใช้ค่าจากแถบบริบทส่วนกลาง การค้นหาและตัวกรองหน่วยงาน/กรอบการประเมินมีผลต่อกราฟ ยอดสรุป และตารางร่วมกัน ตารางแบ่งหน้าละ 20 รายการ แต่ยอดรวมคำนวณจากข้อมูลที่ตรงตัวกรองทั้งหมด

## ความหมายของตัวเลข

- คำของบประมาณรวมทุกสถานะ รวมร่างและยกเลิก ไม่ใช่งบที่ได้รับอนุมัติ
- ความก้าวหน้าเป็นค่าเฉลี่ยรายโครงการที่มีค่า ไม่ถ่วงน้ำหนักด้วยงบประมาณ และรวมทุกสถานะ ไม่มีค่าแสดงว่าไม่มีข้อมูล ไม่ถือเป็นศูนย์
- เบิกจ่ายรวมยอดที่บันทึกทุกสถานะ ยอด `reconciled` แสดงแยก ไม่ควรตีความยอดบันทึกทั้งหมดเป็นการยืนยันยอดจ่ายเงินจริง
- KPI นับรายการผลประเมิน ไม่ใช่จำนวนคำนิยามตัวชี้วัดที่ไม่ซ้ำ หากตัวชี้วัดมีทั้งผลรายปีและรายไตรมาสจะแสดงแยกพร้อมป้ายรอบผล การบรรลุเป้าหมายอ้างอิงสถานะที่บันทึกและต้องมีผลจริง ส่วนการรับรองอ้างอิง `verified` ไม่รวมค่าของตัวชี้วัดต่างหน่วยเข้าด้วยกัน

## แหล่งข้อมูลและสิทธิ์

ใช้ Supabase client ของผู้เข้าสู่ระบบและสิทธิ์เดิม ดึงข้อมูลเป็นชุดละ 500 รายการเรียงตาม ID จนหมด ไม่ใช้ข้อจำกัดจำนวนแถวของไฟล์ส่งออกมาเป็นยอดสรุป เมื่อชุดใดโหลดผิดพลาด จะแสดงข้อผิดพลาดแทนผลรวมบางส่วน ไม่มี SQL migration เพิ่มเติม

## การตรวจสอบ

- `tests/unit/report-dashboard.test.ts`: ค่าเฉลี่ยที่มีข้อมูลขาด ยอดตามไตรมาส การกระทบยอด และผล KPI ที่ยังไม่กรอก
- ตรวจหน้าจอจำลองทั้ง 4 แบบที่ 1440px และ 390px พร้อมค้นหา ล้างตัวกรอง และแบ่งหน้า
- การตรวจหน้าจอใช้ข้อมูลจำลองแยกจาก Production ยังต้องตรวจข้อมูลจริงกับบัญชีที่มีสิทธิ์ก่อนใช้รายงานประกอบการตัดสินใจ
